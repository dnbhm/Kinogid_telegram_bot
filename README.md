# Киногид Vision Мастерской 🎬

Готовый проект Telegram-бота **@Kinogid_vision_bot** на Python и aiogram 3. Пользователи и очередь рассылок хранятся в SQLite. Домен, HTTPS-сертификат и открытый входящий порт не нужны: бот получает обновления через long polling.

## Рассылка интенсива

### Согласованный анонс интенсива — 21 ноября 2026, 12:00 МСК

Код содержит фото, полный текст и URL-кнопку «Вступить в киноклуб🎥» со ссылкой `https://t.me/+xb3ZBglvse5kMGEy`.

Для оформления одним сообщением, как у заказчика:

1. Перешлите боту оригинальный пост из Telegram: фото вместе с полной подписью. Не сообщение с инструкцией про кнопку.
2. Ответьте на пересланный пост командой `/intensive` с администраторского аккаунта.
3. Бот скопирует исходный пост, сохранив подпись и форматирование, и добавит настоящую кнопку.
4. Проверьте копию, дату **21 ноября 2026, 12:00 по Москве** и нажмите «Подтвердить рассылку» до этого времени.
5. Проверьте состояние в `/jobs`. Остановить отправку: `/cancel ID`.

Если исходный пост нельзя переслать, команда `/intensive` без ответа на сообщение подготовит два сообщения: приложенное фото, затем полный текст с кнопкой. Это обходит лимит 1024 символа для новой подписи к фото; полный текст не сокращается.

Получатели выбираются **при начале отправки**, поэтому включаются и пользователи, пришедшие после подтверждения. Этап прохождения бота, ответы на опрос и интерес к обучению не влияют. Исключаются администраторы, отключившие рассылки и заблокировавшие бота. Пользователь, пришедший уже после начала отправки, в эту разовую рассылку не добавляется.

Повторная команда не создаёт повторную рассылку. При перезапуске сохраняется прогресс, в том числе между фото и текстом для варианта с двумя сообщениями. До подтверждения ничего не отправляется аудитории. После истечения согласованного времени создать или подтвердить новый черновик нельзя. Для подтверждённой очереди действуют обычные ограничения: сервис должен работать, а успешная отправка в Telegram и запись результата в SQLite не являются одной транзакцией.

Обновление схемы базы добавляет столбцы и сохраняет пользователей и существующие рассылки. Обеспечьте постоянное хранение SQLite на сервере. Время начала отправки фиксировано в Москве независимо от настройки `TIMEZONE`.

Проверено: 39 автоматических тестов, включая существующую выдачу урока и новую рассылку.
