# Киногид Vision Мастерской 🎬

Готовый проект Telegram-бота **@Kinogid_vision_bot** на Python и aiogram 3. Пользователи и очередь рассылок хранятся в SQLite. Домен, HTTPS-сертификат и открытый входящий порт не нужны: бот получает обновления через long polling.

## Что уже сделано

- Описание перед «Старт» и приветствие после `/start` с вашими текстами, выделениями и ссылкой на Настю.
- Кнопка **«Вступить в киноклуб 🎬»** → сохранение участия → первый пост целиком → вопрос **«кто ты в кино?»** с четырьмя ответами и кнопкой про обучение.
- Ответ на выбор: **«запомнил ✦ увидимся в зале»**. Роль и интерес к обучению сохраняются независимо; их можно менять через `/profile`. Повторное нажатие кнопки обучения с галочкой снимает интерес.
- Участники, их краткая статистика, карточки и CSV для администратора.
- Отправка постов сразу или в заданную дату, выбор аудитории, проверка копии и подтверждение перед отправкой.
- `/stop` отключает все рассылки. `/club` включает их снова. Повторный `/start` не включает сообщения после отписки и не дублирует первый пост.
- Администратор **759470806** исключён из базы пользователей, статистики и получателей рассылок. Можно добавить других администраторов.
- Docker Compose, вариант запуска через systemd и автоматические проверки для GitHub.

**Кнопка вступления означает подписку на киноклуб внутри этого бота.** Отдельный Telegram-чат создавать необязательно. Если он уже есть, добавьте приглашение в `CLUB_CHAT_URL`: после вступления появится кнопка перехода. Бот не проверяет членство в отдельном чате.

**Фильмы, рубрики и ссылки на созвоны добавляет администратор.** Бот не выбирает фильмы и не создаёт видеовстречи сам. Для недельной программы заранее подготовьте несколько постов и назначьте им время командой `/post`.

## 1. Опубликовать код в Git

В репозиторий загрузите **содержимое этой папки**, включая `.env.example`, `.gitignore`, `.dockerignore` и `.github`. GitHub → New repository → Add file → Upload files или обычный Git. Пример для терминала в папке проекта:

```bash
git init
git add .
git commit -m "Initial Kinogid Vision bot"
git branch -M main
git remote add origin https://github.com/YOUR_LOGIN/kinogid-vision-bot.git
git push -u origin main
```

Замените `YOUR_LOGIN` на свой логин. До этого создайте пустой репозиторий без автоматически добавленного README.

**Настоящий токен не вписывайте в код или `.env.example`.** Он хранится только в `.env` на сервере. Этот файл, база и резервные копии исключены через `.gitignore`. Если токен когда-либо оказался в Git, перевыпустите его в BotFather: удалить строку из последнего коммита недостаточно.

## 2. Запуск на сервере — Docker Compose

Понадобится Linux-сервер с Git и Docker Compose. Если у вас другая система или Docker не установлен, ниже есть запуск без Docker.

```bash
git clone https://github.com/YOUR_LOGIN/kinogid-vision-bot.git
cd kinogid-vision-bot
cp .env.example .env
chmod 600 .env
nano .env
```

В `.env` замените значение `BOT_TOKEN` на токен **именно @Kinogid_vision_bot** из BotFather. Остальное можно оставить:

```dotenv
BOT_TOKEN=ВАШ_ТОКЕН_ИЗ_BOTFATHER
ADMIN_IDS=759470806
DB_PATH=data/kinogid.sqlite3
TIMEZONE=Europe/Moscow
CLUB_CHAT_URL=
```

Затем:

```bash
docker compose up -d --build
docker compose logs -f --tail=100 bot
```

Закрыть просмотр журнала: `Ctrl+C`. Бот продолжит работать. Откройте **@Kinogid_vision_bot** и нажмите «Старт».

При запуске код устанавливает описание перед «Старт», краткое описание и меню команд. Описание совпадает с присланным вами; его можно изменить в `kinogid/content.py`. Фото бота и его имя остаются настройками BotFather.

Compose автоматически поднимает бота после перезапуска сервера при включённой службе Docker. База находится в постоянном томе `bot_data`, отдельно от контейнера и репозитория. Обычное обновление её сохраняет:

```bash
git pull --ff-only
docker compose up -d --build
```

Не запускайте две копии с одним токеном. Не запускайте одновременно Docker и systemd. Не используйте `docker compose down -v`: ключ `-v` удаляет том с базой. На сервере должны быть исходящий доступ к `api.telegram.org:443` и правильное системное время.

## 3. Как пользоваться администратору

Откройте бота с аккаунта **759470806**, нажмите «Старт» и отправьте `/admin`.

| Команда | Что делает |
| --- | --- |
| `/admin` | Инструкция по управлению |
| `/stats` | Пользователи, вступления, активность, сегменты, отписки, доставка |
| `/users` или `/users 2` | Пользователи по 20 на странице |
| `/user 123456789` | Карточка конкретного пользователя |
| `/export` | CSV со всеми пользователями без администраторов |
| `/jobs` | Последние 10 рассылок: ID, время, состояние и результаты |
| `/cancel 12` | Остановить рассылку №12; уже отправленные сообщения остаются |

Аккаунты вне `ADMIN_IDS` не могут получить статистику, выгрузить базу, создать или подтвердить рассылку. Скрытое меню само по себе не используется как защита: ID проверяется обработчиками.

Чтобы добавить администратора, перечислите ID через запятую:

```dotenv
ADMIN_IDS=759470806,123456789
```

После изменения `.env` перезапустите приложение: для Docker — `docker compose up -d --force-recreate`. Если новый администратор раньше был пользователем, при старте его запись и связанные записи получателей удаляются из статистики.

### Отправить фильм недели или другой пост

1. Пришлите боту **готовый текст** или **одно фото/видео с подписью**. Можно переслать сообщение из своего канала, если Telegram разрешает его копирование.
2. Выберите это сообщение → **«Ответить»**.
3. Отправьте `/post club`.
4. Бот пришлёт копию поста, аудиторию, время и кнопки. Проверьте копию, затем нажмите **«Подтвердить рассылку»**.
5. Дождитесь сообщения с результатом. Проверить отправку также можно через `/jobs`.

Поддерживаются текст, фото, видео, анимация, документ, аудио, голосовое, кружок и стикер. Разметка и подпись сохраняются через копирование Telegram. Служебные сообщения и альбомы не поддерживаются; отправляйте элементы альбома отдельными постами. Кнопки исходного сообщения не переносятся. Не удаляйте созданную ботом копию поста до завершения отправки.

### Запланировать неделю

Тоже ответьте на нужный пост, указав дату и время **по Москве** при `TIMEZONE=Europe/Moscow`:

```text
/post club 2026-11-09 12:00
/post club 2026-11-11 15:00
/post club 2026-11-13 18:00
```

Это примеры трёх отдельных рассылок: фильм, рубрика и ссылка на созвон. Для каждой нужен свой пост и своё подтверждение. Если указанные даты уже прошли, замените их на будущие. Рассылки одноразовые: для следующей недели добавьте новые.

Бот должен работать в назначенное время. Если сервер был выключен, просроченная подтверждённая рассылка начнётся после запуска. Перед длительным выключением отмените неактуальные посты через `/cancel ID`.

### Выбрать аудиторию

| Значение после `/post` | Получатели |
| --- | --- |
| `club` | Нажали «Вступить в киноклуб» или `/club` |
| `all` | Все, кто взаимодействовал с ботом, включая ещё не вступивших |
| `training` | Отметили желание попасть в Vision Мастерскую |
| `editor` | ✂️ уже монтирую |
| `creator` | 📱 снимаю контент |
| `curious` | 👀 присматриваюсь к монтажу |
| `cinema` | 🍿 просто люблю кино |

Для **любой** аудитории исключаются администраторы, отключившие сообщения и пользователи с известным запретом отправки. Подписка на рассылки включена при первом взаимодействии с ботом; вступление отдельно отмечает участие в клубе. Кнопки роли и обучения не включают сообщения после `/stop`.

Список адресатов фиксируется при подтверждении. Позднее присоединившиеся люди получат следующие рассылки. Перед каждой отправкой повторно проверяются подписка и соответствие выбранному сегменту. Отмена останавливает дальнейшую отправку; запрос, уже переданный Telegram, ещё может завершиться.

## 4. Что хранится и что значит статистика

Один пользователь — одна запись по Telegram ID:

- ID, username, имя, фамилия и язык из профиля Telegram;
- первый и последний контакт, количество `/start`, сообщений и нажатий;
- дата вступления, роль, дата интереса к обучению;
- включены ли сообщения и разрешает ли Telegram отправку;
- число успешно отправленных постов рассылок;
- первый непустой параметр `/start`, если человек пришёл по ссылке с меткой.

Пример ссылки с меткой: `https://t.me/Kinogid_vision_bot?start=instagram`. В карточке появится источник `instagram`. Тексты обычных входящих сообщений и история личной переписки в базе не сохраняются. Для рассылок сохраняются ID сообщений и очередь доставки.

«Активен за 7 дней» означает, что человек писал боту или нажимал кнопки. Telegram не предоставляет боту подтверждения прочтения сообщений: успешная отправка **не означает просмотр**. Даты в карточках и расписании отображаются в `TIMEZONE`, в базе и CSV — UTC. «Новые за 24 часа» — скользящие 24 часа, а не календарный день.

Состояния запрета отправки и отключённых сообщений считаются отдельно и могут пересекаться. При новом контакте с ботом отметка запрета Telegram снимается; `/stop` при этом продолжает действовать.

База и очередь сохраняются после перезапуска. Обработанные адресаты повторно не перебираются. При аварии точно между успешным ответом Telegram и сохранением результата в SQLite один пост может прийти повторно: у `copyMessage` нет ключа идемпотентности. Аналогично, сетевой таймаут после фактической доставки иногда может привести к повтору. Неуспешные доставки видны в `/jobs`; автоматического повторного запуска завершённой рассылки нет.

## 5. Резервная копия

Пользователи хранятся **на сервере**, Git не является резервной копией базы. Создайте согласованный снимок SQLite через встроенную команду, затем скопируйте его на другой носитель:

```bash
docker compose exec bot python -m kinogid.backup /app/data/backup-2026-11-04.sqlite3
docker compose cp bot:/app/data/backup-2026-11-04.sqlite3 ./backup-2026-11-04.sqlite3
```

Смените дату/имя для следующей копии: существующий файл команда не перезаписывает. Вариант без Docker:

```bash
.venv/bin/python -m kinogid.backup backups/kinogid-2026-11-04.sqlite3
```

Обычное копирование только `kinogid.sqlite3` при работающем боте может пропустить данные из WAL — используйте эту команду. Для восстановления сначала остановите бота и сохраните текущую базу отдельно. Восстанавливайте снимок в чистую папку данных, без оставшихся `-wal` и `-shm` от другой базы, под именем `kinogid.sqlite3`, с правами пользователя процесса. В Docker это UID/GID `10001`. После восстановления убедитесь, что будущие рассылки из снимка всё ещё актуальны, и только затем запускайте приложение.

## 6. Запуск без Docker

Нужен Python **3.10+**; для нового Linux-сервера рекомендуется 3.12. В папке клонированного проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
nano .env
.venv/bin/python -m kinogid
```

При обычном запуске бот работает, пока открыт процесс. Для постоянной работы используйте службу systemd.

### systemd на Linux

Пример рассчитан на проект в `/opt/kinogid-vision-bot` и отдельного пользователя `kinogid`. Если используете другие пути или пользователя, измените `deploy/kinogid.service`.

```bash
sudo useradd --system --home-dir /opt/kinogid-vision-bot --shell /usr/sbin/nologin kinogid
sudo git clone https://github.com/YOUR_LOGIN/kinogid-vision-bot.git /opt/kinogid-vision-bot
sudo chown -R kinogid:kinogid /opt/kinogid-vision-bot
cd /opt/kinogid-vision-bot
sudo -u kinogid python3 -m venv .venv
sudo -u kinogid .venv/bin/python -m pip install -r requirements.txt
sudo -u kinogid cp .env.example .env
sudo -u kinogid chmod 600 .env
sudo -u kinogid nano .env
sudo -u kinogid mkdir -p data
sudo cp deploy/kinogid.service /etc/systemd/system/kinogid.service
sudo systemctl daemon-reload
sudo systemctl enable --now kinogid
sudo journalctl -u kinogid -f
```

Для обновления:

```bash
cd /opt/kinogid-vision-bot
sudo systemctl stop kinogid
sudo -u kinogid git pull --ff-only
sudo -u kinogid .venv/bin/python -m pip install -r requirements.txt
sudo systemctl start kinogid
```

### Проверить на Windows

В PowerShell из папки проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\python.exe -m kinogid
```

Закройте локальную копию перед запуском на сервере.

## 7. Где менять тексты и логику

| Файл | Содержимое |
| --- | --- |
| `kinogid/content.py` | Описания, приветствие, первый пост, ответы, названия сегментов |
| `kinogid/keyboards.py` | Кнопки |
| `kinogid/handlers.py` | Сценарии, команды и статистика |
| `kinogid/db.py` | Хранение пользователей и очереди |
| `kinogid/worker.py` | Доставка рассылок, повторы при сбоях, обработка блокировок |
| `.env` | Токен, администраторы, часовой пояс, путь базы, ссылка на чат |

В сообщениях используется HTML Telegram: `<b>жирный</b>`, `<a href="https://...">ссылка</a>`, `<blockquote>цитата</blockquote>`. Символы `<`, `>` и `&` в обычном тексте экранируйте как `&lt;`, `&gt;`, `&amp;`. Один элемент `GUIDE` — одно сообщение; при существенном расширении разделите его на несколько самостоятельных HTML-фрагментов до лимита Telegram.

Документация: [Telegram Bot API — сообщения и описания](https://core.telegram.org/bots/api), [aiogram — long polling](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html), [aiogram — копирование постов](https://docs.aiogram.dev/en/latest/api/methods/copy_message.html).

## 8. Проверки и первая проверка в Telegram

Автоматические проверки не используют настоящий токен и ничего не отправляют в Telegram:

```bash
python -m unittest discover -s tests -v
```

Проверяются путь нового участника через маршрутизацию aiogram, исключение администраторов, права доступа, независимость интересов, повторное вступление, отписка, сохранение очереди, запрет отправки, сетевые ошибки, лимиты Telegram и защита CSV.

После запуска проверьте бота с двух аккаунтов: администраторским и обычным. Администратор может пройти `/start` → вступление → опрос, но его ответы намеренно не сохраняются. Для проверки реальной базы нужен обычный аккаунт. Проверьте `/stats`, `/export`, тестовый пост через `/post club`, затем `/stop` на обычном аккаунте и ещё один тестовый пост — отписавшемуся он не должен прийти.

В подготовленной версии прошли **26 автоматических тестов** на Python 3.10.6. Проверка с реальным Telegram, Docker и вашим сервером выполняется после добавления токена; токен в проект не включён.
